# SSC 形态文档模板

本目录以 `docs/mods/shape-shifter-curse/forms/axolotl.md` 为完成范例，为其余幻形者诅咒（Shape Shifter Curse，SSC）形态保留待填写骨架。模板不参与站点构建；完成核对后，应把相应章节合并到正式形态页，而不是直接发布占位内容。

## 美西螈范例包含的内容

1. 一句话定位：概括核心玩法、优势和主要代价。
2. 阶段总览：列出阶段名称、形态 ID、主要变化和主要限制。
3. 行为：按盔甲槽、生命值、挖掘、近战、饥饿和移动拆分；复杂移动继续拆为步行、疾跑、游泳、速泳、潜行或爬行。
4. 专属数值系统：说明资源上限、恢复、消耗、耗尽后果和界面复用关系。
5. 能力：每项主动或被动能力独立成节，写明触发条件、效果、消耗、冷却、范围和排除目标。
6. 数据值：记录显示名、命名空间 ID 和本地化键名。
7. 历史：按版本记录玩家可观察到的变化。
8. 画廊：提供各阶段交互模型和与 GLTF 完全一致的动画翻译表。
9. 附录：放置详细测试数据、计算过程、例外和已知问题。
10. 来源脚注：标出源码文件、上游提交和不能确认的边界。

## 格式要求

- 常规路线固定使用“初始阶段、第一阶段、第二阶段、永久阶段”，不要使用“0 阶段”或把初始阶段写成第一阶段。
- 先写玩家可观察到的结论，再给公式、源码字段和实现细节；没有证据的数据保留占位，不作推测。
- 游戏时间同时给出 tick 与秒，伤害和生命值使用点数，需要时补充心数；速度统一使用米/秒。
- 表格一列只表达一种口径。阶段表、ID 表和历史表的列顺序与美西螈页保持一致。
- 能力必须写明阶段、触发方式、条件、消耗、冷却、范围、效果和限制；不适用的项明确写“不适用”。
- `FormModelViewer` 前后保留 `prettier-ignore` 注释。动画键必须逐字匹配当前 GLTF 的 `animations[].name`，包括速度后缀。
- 图表只用于比较三组以上的数据，并提供明确的 `ariaLabel`、单位、图例和对应文本或表格。
- 历史只记录可追溯的版本变化；来源脚注至少包含文件路径或类名和核对 commit。
- 正式页面不得保留“待填写”、空表或未经验证的数值。
